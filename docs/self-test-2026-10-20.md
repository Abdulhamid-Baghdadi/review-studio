# Self-test, 20 October 2026

Claude used the app as a new reviewer would, start to finish, on a topic of its own: **design for remanufacturing of
electric motors**. The review was a draft in the browser pane's storage (nothing on disk). Fields were typed,
buttons clicked, screening done by keyboard; where a step needs something from outside (a database export, PDFs),
it came from OpenAlex. Every bug found was fixed, tested and pushed the same day.

**The review:** PCC question, 3 keyword blocks, 3 inclusion criteria and 7 exclusion reasons, 7 method sections,
locked protocol; OpenAlex search, 229 records (1 duplicate); 228 screened (16 by hand, 212 by a title rule as a
stress test); 158 sought, 2 PDFs found, 156 not retrieved; 2 assessed, 1 excluded (E3, a preprint), **1 included**,
charted; flow diagram, checklist, BibTeX, RIS, charting table and review package exported.

## Found and fixed

Severity: 4 data loss or a wrong result · 3 major · 2 minor · 1 cosmetic.

| # | Sev. | Step | What happened | Fix |

| 1 | 4 | Search strategy | The OpenAlex string turned stems into words that do not exist (`motor*` → "motore") or left stems OpenAlex cannot find (`remanufactur` finds 4 papers, `remanufacture` 14,246). | 2 | 4 | Screen papers | Keys typed while a decision was saving went to the same paper and overwrote it: **19 keys gave 1 decision**, and saves ran into each other ("file not found"). | Screening keys run in order, each on its own paper. 213 keys sent at machine speed: 0 wrong. ## Self-test 2, 20–21 October: what self-test 1 left out

**How:** the same topic, built as a review **on disk** (in the experiments folder, `2026-10-20 self-test 2 records`)
with the app's own engine: 228 papers from OpenAlex, 8 open-access PDFs. It was then opened in the browser pane. The
AI steps were run as Claude Code runs them, with the skills and `bin/ai-assist.js` on the disk copy; a small local
bridge copied the review between disk and the pane (the pane cannot use the Windows folder picker).

**Tested:** amendments after locking (record, cancel); a Scopus CSV, a Web of Science plain-text file, an IEEE Xplore
CSV and a BibTeX file, each with 10 duplicates; saving a draft to a folder; the notes on disk as Obsidian reads them
(235 notes, 5,067 property lines, all plain YAML); all four AI modes: 40 title/abstract and 8 full-text suggestions,
1 PDF fetched and attached, 5 papers prefilled for charting, each reviewed in the app.

| # | Sev. | Where | What happened | Fix |
|---|---|---|---|---|
| 22 | 4 | Search & import | A Web of Science plain-text export had no reader: read as CSV, 20 papers became **284 "records"** that went into the PRISMA flow (573 found, 318 duplicates). | A Web of Science reader; a line without a title is never a record; a file with no papers is refused with a plain message. |
| 23 | 4 | Engine | Switching an AI mode after full-text AI was on crashed while writing the protocol ("fulltext" is no stage), and the change **stayed in memory only**: the page showed four modes, the file kept one. | Each AI step has its own name; when an action fails, the review is read again from disk, so the page shows what is saved. |
| 24 | 3 | Search & import | No way to undo a wrong import. | **Undo** for an import that added no paper of its own (it leaves the table and the flow; the file stays); a disabled Undo says why for one that added papers. |
| 25 | 3 | Search & import | After an undo, the next import reused an id (two S05). | Ids are one above every id used, also by a kept export: never given twice. |
| 26 | 3 | Every review | After a reload the app silently opened the draft, so the review looked gone. | The draft bar offers **↩ Back to (review)**: one click, which is also what Chrome needs to grant the folder again. |
| 27 | 3 | Decision log | An AI-suggested decision was logged as "reviewed" whether the reviewer kept or changed it. | "AI suggestion kept by the reviewer" or "… changed by the reviewer". |
| 28 | 3 | Full-text AI | The skill allowed "unsure", which the full-text stage does not have: the paper left the To do queue and was counted nowhere. | Full-text suggestions are include or exclude; an unclear paper gets none and is named in the report; an older full-text "unsure" counts as still to decide. |
| 29 | 3 | Charting AI | The AI's basis (full text or abstract) was dropped when the form has no "basis" field, so papers read in full showed "AI · abstract". | The basis is always kept; without one the page says "AI · check it". |
| 30 | 3 | Retrieval skill | It told Claude to send **the user's email** to Unpaywall. | It uses OpenAlex (no email); Unpaywall only with an address the user gives for it. |
| 31 | 3 | Draft | The draft lives in the browser's storage, which a browser may clear (the pane cleared it twice). | The app asks for persistent storage; the draft bar says "only in this browser", with **Save to a folder…**. |
| 32 | 2 | Chart the data | "Checked — next" stayed on the paper; "Undo checked" turned an AI prefill into "to chart". | It moves on; Undo puts back the status before. |
| 33 | 2 | Amendments | Shown as "concepts", "queries" (internal keys) in the app and the timeline note; the dialog said "concept table". | Named in words: keyword blocks, search strings and databases, inclusion and exclusion rules … |
| 34 | 1 | Several | "tab" in the skills and AI messages (the app has no tabs); "U" offered at full text; "08 - Records" as a column header; "Git commit: —" in the timeline. | Wording fixed. |
